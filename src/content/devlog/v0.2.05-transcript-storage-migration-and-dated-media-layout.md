## Release focus
Version **0.2.05 (2026-03-06)** was a cleanup and migration release focused on making the file layout more durable before further voice and transcript features were layered on top.

Primary outcomes:
- move to a canonical dated media structure
- consolidate transcript persistence around structured JSON
- eliminate stale no-speech and terminal pending artifacts left from earlier flows

## HUDs impacted
- Voice Recorder HUD
- Audio Files HUD
- Files HUD
- Settings HUD

## Added
- Added one-time startup migration for legacy structured transcript files so older data is moved into the canonical transcript location automatically.
- Added one-time startup migration for dated storage layout:
  - `memory/audio_recordings/YYYY-MM-DD/`
  - `memory/audio_transcriptions/YYYY-MM-DD/`
- Added one-time startup migration for monthly log folders:
  - `memory/logs/YYYY-MM/log_YYYY-MM-DD.txt`
- Added repository support for startup relink flow through recent-record access.

## Changed
- Changed transcript storage to a **structured-only JSON** model under `memory/audio_transcriptions`, removing the old text transcript path as the primary source of truth.
- Changed backup and restore logic to recurse through dated and monthly subfolder structures instead of assuming flat folders.
- Changed Files HUD transcript lookup to resolve canonical `.json` transcript payloads from the new layout.
- Changed Files HUD folder ordering so date-like folders surface first in descending order.
- Changed optimizer/deleted status cleanup flow to better align history state with transcript recovery outcomes.

## Fixed
- Fixed blank or no-speech segments being left behind as pending optimizer artifacts.
- Fixed transcript recovery loops that were continuing after terminal no-transcript cases.
- Fixed log writer path handling for the new monthly logs layout.
- Fixed stale file-provider declarations that still referenced removed `audio_transcriptions_structured` paths.

## Feedback
This was a structural release more than a feature release. The main value was reducing storage ambiguity and making transcript/media persistence predictable enough for later transcript tooling, search, and recovery features.
