## Release focus
This update combines **Walker XR v0.2.04** and **Walker-Desktop v0.0.2** in one stage.

Primary outcome:
- make transcript processing more deterministic from end to end
- support structured, speaker-aware transcript payloads
- stop endless pending loops for terminal failures/no-speech segments

## Systems impacted
- Walker-Desktop optimizer + dashboard
- Walker XR transcript recovery + optimizer sync flow
- Voice Recorder HUD / Audio Files HUD / Files HUD / Settings HUD (status behavior and cleanup effects)

## Walker-Desktop v0.0.2
### Added
- Added structured transcript generation (`.structured.json`) with timestamps and speaker annotations.
- Added a full local speaker pipeline (`speakers.py`) with profile/sample storage, embeddings, clustering/matching, and unknown-speaker handling.
- Added speaker management API surface and dashboard controls (enroll, sample playback, rename, tag, merge, delete, reindex).
- Added `GET /v1/structured` for structured transcript retrieval.

### Changed
- Changed optimizer metadata to include structured transcript file references.
- Changed no-speech handling to delete empty artifacts and mark the recording as `deleted` in metadata.
- Changed dashboard jobs panel to latest 10 jobs for cleaner monitoring.

### Fixed
- Fixed speaker merge behavior to preserve and reuse merged sample context for future matching.
- Fixed merge stability/count edge cases around sample recompute fallback.

## Walker XR v0.2.04
### Added
- Added deleted-status tracking from desktop optimizer into app-side status refresh.
- Added per-recording desktop status/error lookup during transcript recovery.
- Added DB delete-by-id path for optimizer-driven cleanup of deleted recordings.

### Changed
- Changed transcript recovery to explicit result states (`Success`, `RetryableFailure`, `TerminalFailure`) instead of generic retry loops.
- Changed pending-item selection to exclude failed keys.
- Changed status hydration to keep failed records as failed and remove desktop-deleted records.

### Fixed
- Fixed repeated `Transcript recovery finished without text` loops for terminal failures.
- Fixed stale `Transcript pending` rows for no-speech segments by purging local DB/file artifacts when desktop reports `deleted`.
- Fixed local app/desktop status drift by synchronizing optimized/failed/deleted key sets during refresh.

## Feedback
This was an important reliability milestone before new feature expansion: the desktop now provides richer transcript intelligence, and the app now reacts correctly to terminal outcomes instead of accumulating unresolved pending entries.
